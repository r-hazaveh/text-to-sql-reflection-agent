# پروژه Text-to-SQL با بازاندیشی نحوی و معنایی

این نسخه بر اساس مشخصات و تصاویر صورت‌مسئله بازسازی شده است. پایگاه داده دقیقاً چهار جدول `Customer`، `Account`، `Transaction` و `Transfer` دارد و ۹ سؤال ارزیابی داخل `evaluation_queries.py` پیاده‌سازی شده‌اند.

## فایل‌ها
- `setup_db.py`: ساخت و پرکردن `bank_database.db` با داده‌های نمونه
- `agent.py`: اجرای امن SQL و کنترل مسیرهای بازاندیشی
- `backend.py`: زنجیره‌های واقعی LangChain LCEL و بک‌اند دمو برای اجرای آفلاین
- `app.py`: رابط خط فرمان
- `evaluation_queries.py`: پاسخ‌های SQL مرجع برای ۹ سؤال صورت‌مسئله
- `tests/test_agent.py`: تست‌های خودکار
- `TextToSQL_Report.ipynb`: گزارش و مراحل اجرا در نوت‌بوک
- `گزارش_نهایی_Text_to_SQL.pdf`: گزارش فارسی همراه با تصویر خروجی‌ها
- `outputs/`: لاگ اجرا، نتایج ارزیابی و اسکرین‌شات‌های ساخته‌شده از خروجی واقعی
- `docs/text_to_sql.html`: نسخه راهنمای تعاملی صورت‌مسئله برای مراجعه آفلاین

## نیازمندی‌ها
Python 3.10 یا جدیدتر. در پوشه پروژه دستورات زیر را اجرا کنید.

### Windows PowerShell
```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python setup_db.py
```

### macOS / Linux
```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python setup_db.py
```

## اجرای آفلاین و تست
این دستورات به API Key نیاز ندارند:
```bash
python setup_db.py
python app.py --demo
python evaluate_queries.py
python -m unittest discover -s tests -v
```
برای خلاصه تعداد ردیف‌های پاسخ هر سؤال:
```bash
python app.py --evaluate
```

دمو از `DemoBackend` با پاسخ‌های قطعی استفاده می‌کند تا بتوان مسیر اصلاح خطای نحوی و اصلاح یک‌باره خطای معنایی را بدون هزینه API آزمایش کرد. این خروجی، نتیجه تولید زنده مدل زبانی نیست.

## اجرای مدل زبانی واقعی با LangChain و OpenAI API

**نکته امنیتی:** کلید API را در فایل پایتون، نوت‌بوک، گزارش، ZIP یا گفت‌وگو قرار ندهید. فایل `.env` در `.gitignore` قرار دارد و نباید به دیگران ارسال شود. اگر کلیدی در جایی منتشر شد، آن را از پنل OpenAI باطل کنید و یک کلید تازه بسازید.

### Windows PowerShell
```powershell
Copy-Item .env.example .env
notepad .env
```
فایل `.env` را باز کنید و خط زیر را با کلید جدید خودتان تکمیل کنید؛ کلید را بدون علامت نقل‌قول وارد کنید:
```text
OPENAI_API_KEY=کلید_جدید_خودتان
```
سپس فایل را ذخیره و اجرا کنید:
```powershell
python app.py --model gpt-4o-mini --question "Which customers have inactive accounts?"
```

### macOS / Linux
```bash
cp .env.example .env
nano .env
python app.py --model gpt-4o-mini --question "Which customers have inactive accounts?"
```

اگر پرسش را به‌صورت آرگومان ندهید، برنامه آن را در ترمینال از شما می‌پرسد:
```bash
python app.py
```

این حالت به اینترنت، وابستگی‌های نصب‌شده، کلید معتبر و فعال، دسترسی به مدل انتخابی و فعال‌بودن پرداخت/اعتبار API نیاز دارد. اشتراک ChatGPT Plus به‌خودی‌خود اعتبار API فراهم نمی‌کند و فراخوانی‌های API ممکن است هزینه داشته باشند. برای اجرای محلی بدون API از `python app.py --demo` استفاده کنید.

## بررسی اتصال زنده به API

پس از ساخت `.env` با یک کلید تازه و معتبر، ابتدا می‌توانید یک درخواست واقعی و کم‌حجم را آزمایش کنید:
```powershell
python verify_live_api.py --smoke-only
```
اگر خروجی `API CHECK: PASSED` بود، درخواست واقعی به مدل رسیده و پاسخ مورد انتظار دریافت شده است. برای آزمایش یکپارچه تولید SQL، اجرای کوئری و بازاندیشی نحوی/معنایی اجرا کنید:
```powershell
python verify_live_api.py
```
این بررسی زنده ممکن است چند درخواست API و هزینه اندکی ایجاد کند. کلید API هرگز چاپ یا در فایل خروجی ذخیره نمی‌شود. اگر کلید در گفت‌وگو یا جایی عمومی منتشر شده، ابتدا آن را باطل کنید و کلید تازه بسازید.

**محدودیت آزمون این بسته:** تست‌های محلی، دیتابیس، دمو و ۹ کوئری مرجع در محیط ساخت اجرا شده‌اند. درخواست زنده به OpenAI در محیط ساخت انجام نشده است؛ برای همین اسکریپت بالا اضافه شده تا اتصال واقعی با کلید خصوصی خودتان روی سیستم شما قابل تأیید باشد.

## معماری
1. تولید SQL اولیه با زنجیره LCEL.
2. اجرای کوئری روی SQLite.
3. در صورت خطای نحوی/ساختاری، ارسال SQL و پیام خطا به زنجیره اصلاح؛ حداکثر سه تلاش اجرای SQL.
4. پس از اجرای موفق، یک فراخوانی Semantic Critic برای ارزیابی هم‌خوانی پرسش، SQL و نتیجه.
5. در صورت ارائه اصلاح معنایی، کوئری اصلاح‌شده فقط یک بار اجرا می‌شود؛ حلقه معنایی تکرار نمی‌شود.

## ایمنی
- فقط `SELECT` و CTEهای خواندنی پذیرفته می‌شوند.
- SQLite authorizer دستورات نوشتنی و تغییر ساختار را رد می‌کند.
- اجرای چند دستور در یک ورودی مجاز نیست.
- سقف تلاش‌های نحوی قابل تنظیم است.

## نکته درباره نتایج
تست‌ها و کوئری‌های مرجع با دیتابیس محلی اجرا می‌شوند. برای پرسش‌های آزاد و تولید SQL توسط مدل واقعی، خروجی به کیفیت مدل و API متصل‌شده بستگی دارد و باید بررسی شود.
